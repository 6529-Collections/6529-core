# Desktop signed and encrypted messages

Core supports app grants and content-free encrypted desktop notifications. This follow-up preserves a private receiving-device setup fragment through deep links, passes optional encrypted setup through the native auth bridge, and removes connection credentials from native navigation logs.

The wallet approves fresh receiving-app keys in the source browser; the target Core app never needs to connect the wallet. Existing target keys and local history are preserved by the companion frontend.

[Frontend #4541](https://github.com/6529-Collections/6529seize-frontend/pull/4541) owns setup acceptance, encrypted inbox entries and the status indicator. **Refresh the renderer from frontend main through `pull-web` after that PR merges**, keeping Core's native-auth adaptations and the encrypted setup fields. [Backend #2287](https://github.com/6529-Collections/6529seize-backend/pull/2287) requires `dbMigrationsLoop → api` before the new frontend flow. Mobile companion: [#26](https://github.com/6529-Collections/6529-core-mobile/pull/26).

No renderer subtree import, build, signing, upload or app release was performed in this implementation. Real source-wallet approval and receiving-app acceptance remain staging release checks.
