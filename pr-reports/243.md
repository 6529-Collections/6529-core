# PR Report: Native four-wallet TDH and shared policy

PR: [Core #243](https://github.com/6529-Collections/6529-core/pull/243)
Branch: `agent-prxt/native-four-wallet-tdh` → `main`
Related: [BE #2148](https://github.com/6529-Collections/6529seize-backend/pull/2148), [BE #2151](https://github.com/6529-Collections/6529seize-backend/pull/2151), [FE #4218](https://github.com/6529-Collections/6529seize-frontend/pull/4218)

## Summary
The native delegation index and TDH calculation support four-wallet grouping with directional block timestamps and a resumable, archive-free replay. The cutoff and both wallet limits now come from the selected backend’s public settings instead of duplicated Core constants.

## What Changed
- Historical delegation scanning uses logs and block headers. Scope comes from events; expiry is read from surviving contract entries at bounded recent snapshots, allowing fresh sync and Reset with AWS full-node RPCs.
- A durable registration ledger retains each block/log position, timestamp and exact token scope, including oversized-token placeholders. Reconciliation matches full entry metadata before accepting expiry and handles Safe/batch/manager calls and same-block revocations/renewals.
- Version-two replay stages both initial and incremental changes, resumes log and expiry progress, and publishes live rows atomically only when all pending registrations are verified. Older partial replay formats restart their shadow state once while preserving live data.
- Scheduled TDH and incremental NFTDelegation reconsolidation obtain one settings snapshot per calculation containing the cutoff, maximum group size and ungated boundary. Native staging requests use existing private authentication; no renderer secret is introduced.
- Missing, invalid or unavailable settings defer calculations before TDH writes and preserve displayed results; event indexing can continue with recalculation marked pending.
- Every grouping path uses that snapshot, including holding-time calculations, aggregated groups and missing-wallet rows.
- A nullable TDH completion field records the selected endpoint/cutoff and both wallet limits. A changed policy forces full regrouping instead of mixing incremental results with an older cutoff.
- Timestamp contract regressions distinguish valid nonzero whole seconds (both `Z` and `.000Z`, with identical policy identities) from invalid seconds, day rollover and fractional seconds. Backend settings serialize valid cutoffs through `toISOString()`; strict calendar validation remains intentional.
- Worker cards wrap long status messages and RPC payloads within the available width. New worker failures prefer a concise RPC reason, bounded to 240 characters; Logs retain the original error message and stack.
- Worker cards separate the operation and current action with a dash. Expiry reconciliation displays the percentage of registrations durably verified, including progress retained after interruptions.

## Desktop Impact
Changes cover the main process, native workers, SQLite entities and the Core worker-card error display. No renderer subtree sync or desktop version bump is included.

## Config / Env
No Core cutoff or limit setting is added. The backend retains code constants 4 and 3, exposed as `consolidation.max_wallets` and `ungated_max_wallets`; no maximum-wallet secret or additional API call is introduced. Configure `CONSOLIDATION_FOUR_WALLET_ACTIVATION_AT` on the backend and deploy its `/api/settings` contract first. Production launch is October 15, 2026 at 00:00 UTC; the test backend can supply an earlier date. Native settings requests are bounded and never fall back to a production date.

## Risks / Follow-Ups
Existing databases add the nullable policy field, registration ledger tables and replay/checkpoint fields through normal synchronization. The upgraded version-two index rebuilds once; live rows remain available until completion. Expiry reconciliation describes currently surviving registrations, including expired-but-unrevoked entries; it does not reconstruct expiry for revoked historical registrations. A policy change, or a missing policy key on first upgrade, makes the next event-driven TDH calculation a full run. Settings failures preserve results until a scheduled/manual or later consolidation-triggered calculation succeeds. The UTC whole-second format is an intentional backend/client contract; accepting arbitrary date formats is not part of this change. Test with dedicated mainnet wallets; links made before production’s cutoff must be renewed for production eligibility.
